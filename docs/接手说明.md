# 赛事沙盘 · 小黑盒小程序 接手说明（2026-10-22 核对版）

> 目的：让接手的人能在半小时内跑通、知道哪里容易踩坑、知道发版链路怎么走。
> 本文件只写**当前有效**的结论；历史决策与排障细节见开发记录（不在本仓库内，向负责人索取）。

---

## 1. 一句话说明

黑盒社区里的「电竞赛事胜负预测模拟盘」。玩家用虚拟道具「沙粒」对真实比赛猜胜负，猜对得沙粒、连对加成、沙粒不够可「采沙」，另有排行、分享、成就。**不涉及真实货币**，不可充值/兑换/交易。

覆盖 10 个项目：CS2、Dota 2、英雄联盟、无尽对决、彩虹六号、王者荣耀、守望先锋、瓦罗兰特、星际争霸2、火箭联盟。

## 3. 跑起来

```bash
npm install
npm run dev          # = hb-sdk dev，默认 5176 小程序 / 5177 调试台
npm run build        # 出 dist/（待上传文件 9 个 / 约 1.6 MiB）
```

调试台地址：`http://127.0.0.1:5177/?mini_url=http%3A%2F%2F127.0.0.1%3A5176%2F`

- `npm run lint` / `npm run check` **不存在**。
- 沙箱终端里 `npm run build` 可能报 `spawn EPERM`（vite 要 spawn 探测真实路径），普通终端不受影响。
- `TaskStop` 停后台任务**不会**杀掉 `hb-sdk dev` 子进程，端口会继续占用：`netstat -ano | grep :5176` 找 PID，`taskkill //PID <pid> //F`。

## 4. 数据链路（当前形态）

```
PandaScore ──> tools/fetch-matches.mjs ──> data/matches.json
                                              │
                     ┌────────────────────────┴─────────────────────────┐
                     │                                                  │
     构建时内嵌进小程序（兜底）                        runtime/matches.json + meta.json
                                                                        │
                                              GitHub Actions 每 5 分钟采集
                                              → Release 资产 + 自动同步 OSS
                                                                        │
                                    客户端启动时拉 meta.json（hash 变了才拉 matches）→ 缓存
```

- 运行时基址：`https://esports-sandbox-data.oss-cn-hangzhou.aliyuncs.com/`
- `network` 权限 **已获批**（2026-10-22），线上快照 `enabled`；`1.1.0` 起生效
- 客户端**只在启动时**检查一次更新（`refreshData()` 无定时轮询），失败静默回退缓存/内置数据
- 拉最新数据：`gh release download data --repo zhuran305-web/esports-sandbox --pattern matches.json --dir data --clobber`（`npm run data:pull` 在 github.com 被墙时会超时）

## 5. 发版流程（每一步都别漏）

1. 拉数据 → `npm run runtime:build` → `npm run runtime:publish -- --upload --check`（看到「匿名读取 OK · N 场」）
2. **两处**版本号同步：`package.json` 与 `js/app.js` 的 `APP_VERSION`
3. 构建：`VITE_RUNTIME_DATA_BASE=https://esports-sandbox-data.oss-cn-hangzhou.aliyuncs.com/ npm run build`
4. 核对：`dist/manifest.json` 的 version / sdkVersion、`grep oss-cn-hangzhou dist/assets/*.js`、无凭据泄漏
5. 提审：**同一条命令也要带环境变量**（deploy 会自己重新 build）
   `VITE_RUNTIME_DATA_BASE=... npx hb-sdk remote deploy --release-note "..."`
6. 过审后 `npx hb-sdk remote release <version> --yes`（非交互必须 `--yes`）
7. `npx hb-sdk remote info` 确认 `Version` 与 `network: 线上快照=enabled`
8. 提交并推送代码（`git push` 被墙就重试，不要用 Git Data API 重建 hash）

**平台限制**：只允许一个待审/待发布版本；旧版本即使 `approved` 未 `release` 也占位，`deploy` 前要 `remote withdraw <版本> --yes`（不可逆）。

## 6. 审核期的已知现象

用 `npx hb-sdk remote preview <version>` 打开**未发布**版本时，首页会弹宿主原生 `SERVER_API_REQUIRED`——预览版本的 effective network 没生效，启动时的 `network.request` 被宿主拦下。发布后即消失，不是代码缺陷。

## 7. 容易踩的坑（都已踩过，详情见开发记录）

1. **`@media` 不提升特异性**：窄屏规则必须写在基础规则**之后**，否则整段失效。
2. **`hidden` 只是 `display:none`**：3000 行的赛程表再次显示会整树重排，进入前要先清空。
3. **分帧不要只靠 rAF**：宿主切页/后台会暂停，用 rAF + `setTimeout` 双保险。
4. **`scrollTo(0,0)` 要在隐藏旧视图之前**，否则长页缩成短页会闪白。
5. **SDK 只有一个出口**：只有 `js/platform.js` 能 `import` hb-sdk，`app.js` 里直接引会让 `isMiniProgram()` 判断飘。
6. **渲染性能约定**：`renderAll` 只渲染可见视图、`matchById` 是 Map（`applySnapshot` 后要 `rebuildMatchIndex()`）、`renderMatches` 复用 `statusMap`——改动前看开发记录「渲染性能约定」。
7. **`.env` 不进仓库**：OSS 凭据只在本机 `.env` 与 GitHub Secrets。

## 8. 发版前检查清单

- [ ] `git status` 干净，没有夹带调试代码
- [ ] `package.json` / `js/app.js` 版本一致，`dist/manifest.json` 一致
- [ ] 构建带 `VITE_RUNTIME_DATA_BASE`，产物里能 grep 到 OSS 域名
- [ ] `remote publish` 校验通过，OSS 上的 `updatedAt` 是最新
- [ ] `remote info` 权限行没有异常（`share`、`network` 应为 enabled）
- [ ] 真机过一遍：下注、结算、排行榜、分享、设置/赛程/玩法返回层级
