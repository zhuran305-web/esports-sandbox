# 人物表情、头发结构与复杂度基线

## 使用范围

输入含人物、拟人角色、清晰五官或头发时使用本节。先判断“还需要多少面部信息才能识别主体”，再选择五官；不要把原图全部五官等比例搬进图标。

## 五官判断树

将眼睛、鼻子、嘴视为三类信息。默认只使用 0–1 类，语义确实需要时最多使用 2 类；三类同时出现为不合格。

先执行“原表情优先”检查：若源图表情由 1–3 个清晰几何形状组成，只使用 0–2 类五官，且在 24 px 下仍能准确读出情绪，则保留它的眼型、倾角、开合和嘴形，只统一线宽、圆角、间距与五色用法。火焰上的斜切怒眼、角色的一枚简洁嘴或一对明确豆豆眼都属于可直接保留的情况。只有源表情模糊、过细、类别过多、依赖纹理，或缩小后情绪失真时，才进入下面的模板判断。

1. 轮廓、发型、服装、手势或配件已经能说明主体时，使用 `none`：完全不画五官。长发英雄剪影一类图标以发型和负形承担识别，不需要在白色脸区补眼口。
2. 需要让用户明确感知“这里是一张脸”或需要视线方向，但情绪不是核心时，使用 `eyes`：只保留一对豆豆眼或一对短弧眼。`捏脸`参考使用两枚竖向豆豆眼；不添加鼻和嘴。
3. 语义是组队、交流、欢呼、发声或亲和感，而视线方向不重要时，使用 `mouth`：只保留一个居中的嘴部符号。`小黑盒_组队`参考使用一枚横向半椭圆嘴；不添加眼和鼻。
4. “可爱、友好、开心”等情绪本身是识别信息时，使用 `eyes mouth`：采用倒 U 眼加短 W 嘴。不要再添加鼻子、瞳孔、眼眶或面颊纹。
5. 只有当鼻子、喙、口鼻部或嗅觉特征决定角色身份时才使用 `nose`。鼻子可单独出现，也可与眼睛或嘴二选一组合；一旦保留鼻子，绝不同时保留眼睛和嘴。

眼镜、面罩、刘海遮挡、手部遮挡均计入面部信息密度。存在其中任一项时，优先把五官预算降为 0–1 类；例如眼镜人物只在镜片内保留短眼或豆豆眼，不再补鼻和嘴。

人物或拟人角色在根 `<svg>` 上写入 `data-face-features`，合法值为 `none`、`eyes`、`mouth`、`nose`、`eyes mouth`、`eyes nose`、`mouth nose`。声明必须与实际绘制一致；审核脚本会拒绝眼、鼻、嘴三类同时声明。

## 表情模板

以下模板都是后备方案，不是必须套用的标准答案；已通过“原表情优先”检查时不要替换原表情。

- `assets/expression-template-bean-eyes.svg`：两枚竖向豆豆眼，适合中性、专注或仅需面部存在感的角色。
- `assets/expression-template-mouth-only.svg`：单一半椭圆嘴，适合组队、交流和亲和语义。
- `assets/expression-template-yimo.svg`：短弧眯眼加圆鼻，适合坚定、俏皮或需要中心口鼻特征的角色；已删除嘴部，避免三类五官同时出现。
- `assets/expression-template-rock.svg`：倒 U 笑眼加 W 形小嘴，适合可爱、轻松、友好的情绪；不添加鼻和瞳孔。

五官保持 1–3 个可见几何元素：一对眼可以合并为一条双子路径，鼻或嘴各占一个元素。表情描边使用 4.2 px；粗实体眼可用约 6.4 px，并保持圆端点。只微调眼距、倾斜、弧度和嘴角，不逐笔描摹原图。

眼睛与嘴必须分属清楚的上下区域。按包含描边后的实际可见边界计算，154 px 画布下眼形底部与嘴形顶部默认至少保留 `4.2 px` 净距；只有源图的语义明确要求五官相连时才允许接触。星形眼、斜眼等大眼形应先缩小或上移，不能侵入嘴区；汗滴、泪滴和面颊符号放在眼区外侧或上方，不能夹在眼与嘴之间造成第三个五官或错误重叠。缩到 24 px 后，眼和嘴仍应是两个可分别读出的形状。

## 头发与头部结构

- 头发和头部必须共用一条最外层轮廓。先绘制完整头发/头部基面，在其中裁切脸部亮面与额前发块，最后只重画一次外轮廓。
- 额前发块是内部色面，不是独立帽子。发块可以使用闭合路径完成填充，但其外侧边必须被头部裁切，且自身不得画完整闭合描边。
- 发际线或刘海下沿使用 1–3 条开放曲线表示，线端必须接触外轮廓或略微进入外轮廓下方，使描边自然被外轮廓收口。不得沿发块上沿再画一圈与头部平行的线。
- 禁止在发块与头部外轮廓之间保留底色缝、透明缝或两条等距粗线。154 px 预览中如果头发能被看成单独扣上的“盖子”，必须返工。
- 48 px 检查时，外轮廓应连续，发际线只承担内部结构；缩小后若出现一圈白缝、底色缝或双重轮廓，同样判定不合格。

## 复杂度量化

两个 154×154 参考 SVG 的实测值：

| 参考 | 几何元素 | 路径命令 | 非透明面积 | 边界密度 |
|---|---:|---:|---:|---:|
| 伊莫 | 21 | 272 | 12624 px | 28.5 |
| 洛克王国 | 28 | 297 | 15155 px | 35.5 |

结构数量只用于解释，不直接作为合格线；路径可合并或拆分，单看节点数容易误判。最终以 154 px 渲染后的“透明边界与明显色差边界总量 / 非透明面积平方根”作为视觉边界密度。两张参考的中位数约为 `32.0`，复杂人物默认允许 `25.5–38.5`。低于区间通常信息不足，高于区间通常是轮廓重复、色面切割太碎或五官/发丝过多。

运行：

```bash
node scripts/svg-icon-tool.mjs complexity output.svg \
  --reference reference-a.svg \
  --reference reference-b.svg
```

有同组参考时按参考中位数并允许约 `±20%`；没有参考时使用上面的内置范围。复杂度超标时，优先删除重复轮廓、细发丝、次要衣褶、第二套高光和不影响身份的内部线，不得通过缩小整图或合并成不可编辑位图降低数值。
