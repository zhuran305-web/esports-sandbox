# 赛事沙盘 · 小黑盒小程序 接手说明（2026-10-26 核对版）

> 目的：让接手的人半小时跑通、知道坑在哪、发版链路怎么走。只写**当前有效**结论；历史与排障细节见开发记录（仓库外，向负责人索取）。

## 1. 一句话说明

黑盒社区里的「电竞赛事胜负预测模拟盘」。沙粒为虚拟道具，猜胜负、连对加成、可采沙，另有排行榜、分享、跨设备战绩同步。**不涉及真实货币**。覆盖 10 个项目（随采集浮动）：CS2、Dota 2、英雄联盟、无尽对决、彩虹六号、王者荣耀、守望先锋、瓦罗兰特、星际争霸2、火箭联盟。

## 3. 跑起来

```bash
npm install
npm run dev          # 习惯端口：--port 5176 --browser-dev-host-port 5177
npm run build        # 必带 VITE_RUNTIME_DATA_BASE=<OSS 基址>，产物 dist/ ~750KiB/9 文件
npm run test:cloud   # 榜单/昵称冒烟测试（stub SDK 直跑 js/cloud.js + app.js 静态检查）
```

- 调试台：`http://127.0.0.1:5177/?mini_url=http%3A%2F%2F127.0.0.1%3A5176%2F`
- 没有 lint/check 命令；沙箱终端 build 可能 `spawn EPERM`（普通终端正常）
- TaskStop 杀不掉 hb-sdk dev 子进程：`netstat -ano | grep :5176` → `taskkill //PID <pid> //F`
- 调试宿主（Browser Fake）里 `cloud.storage` 必报 `METHOD_FORBIDDEN`，自动降级，非故障
- `.env`（gitignore）：OSS AK + `USER_MINIPROGRAM_ID/SECRET`（换票凭据，只进 FC 环境变量）

## 4. 数据链路

```
PandaScore → Actions 每 5 分钟 → Release 资产（变化才覆盖）+ OSS 同步（漂移自愈）
客户端：内置 4+16 天窗口快照（冷启动先渲染）→ 运行时每 5 分钟轮询 OSS
        （meta 探测，hash 变才拉 1.2MB 整包；show 回前台刷新；限流退避 15 分钟；失败回退缓存/内置）
```

- 基址 `https://esports-sandbox-data.oss-cn-hangzhou.aliyuncs.com/`（network 已批、线上快照 enabled）
- **build 与 deploy 都必须带 `VITE_RUNTIME_DATA_BASE`**（deploy 会自己重建）
- 拉最新数据：`npm run data:pull`（github 被墙时用 `gh release download data --pattern matches.json --dir data --clobber`）

## 5. 发版流程

1. 两处版本号同步：`package.json` + `js/app.js` 的 `APP_VERSION`
2. 构建：`VITE_RUNTIME_DATA_BASE=<基址> npm run build`；核对 `dist/manifest.json` 与产物 grep OSS 域名、无凭据；`npm run test:cloud` 全过
3. 提审：同一条命令带环境变量 `npx hb-sdk remote deploy --release-note "..."`
4. 过审后 `npx hb-sdk remote release <版本> --yes`；`remote info` 确认 network=enabled
5. 推送代码（push 被墙先重试直推；仍失败用 **Git Data API 整树推送**：GET ref → POST /git/trees（content 内联）→ POST /git/commits → PATCH ref，走 api.github.com；**推送后回读远端 tree sha 与本地 `git rev-parse HEAD^{tree}` 比对**；连通恢复后 `git pull --rebase` 去重）

**平台限制**：单待审位（approved 未 release 也占位）；`withdraw` 不可逆、须负责人当轮确认；审核时长 3 分钟~10 小时+不可预期。

## 6. 身份与换票（1.1.17+ 架构，全平台一致）

- **不用 `user.getInfo`**（鸿蒙生产态+授权后仍弹宿主原生 `SERVER_API_REQUIRED`，工单 2323841；代码已移除该调用）
- 身份 = 榜单通道 `getCurrentUserEntry().appUserId`（boot 自动注册 0 分条目保证可读）；isMe 用 `Cloud.getMyUid()`——**cloud.js 模块私有变量不可在 app.js 裸引用**（曾致 1.1.14~1.1.23 榜单页全平台空白 9 个版本）
- 榜单只展示有战绩的条目（`renderBoard` 过滤 `first<=0`；score=场次×10⁹+沙粒保证 0 分沉底、过滤后名次连续）；0 场用户「我的成绩卡」显示引导文案
- 昵称头像 = **授权换票**：设置页/引导页「同步黑盒资料」→ `auth.login`（保留在代码中，须用户手势）→ GET **直连 FC** `<fc域名>/api/exchange/<一次性code>`（1.1.26 起；传输层失败自动降级 OSS 回源）→ OpenAPI → 缓存本机 → 昵称随榜单 extra 提交（昵称变化即时上榜）；**已同步账号重复点击直接短路（1.1.27 起，防重复 FC 计费）**
- 昵称链：黑盒资料 → 自选展示昵称 → 榜单 extra → 「盒友·ID后4位」
- **换票链路硬约束**（改前必读，详见开发记录）：回源规则只能 OSS 控制台配（REST 网关不认 mirror 子资源；携带请求字符串=携带；禁止透传 host/authorization）；FC 必须**恒 200**（错误入 body）；**code 必须在路径里**（回源缓存键只按路径且必落桶，query 传参会串号）；函数变更 `node tools/deploy-identity-fc.mjs`（幂等），不需动回源规则
- **域名口径（2026-10-26 官方答复）**：network 批准后访问第三方 HTTPS 域名**无需再次申请**——新服务直接直连 HTTPS 即可；OSS 回源仅作为现状实现与旧客户端兜底（待 1.3.396+ 真机实测复核）
- FC 成本 ≈ 每月几毛~2 元（CU+活跃小时最低计费）；**欠费会停函数**，账户常驻 ≥10 元
- 排障入口：设置→关于小程序→「环境诊断」行（模式/系统/版本一图定位）；错误码即宿主指纹（SERVER_API_REQUIRED=鸿蒙门禁、REQUEST_FAILED=卓易通兼容层）

## 7. 容易踩的坑（详情见开发记录「陷阱条目」）

1. `@media` 不提升特异性：窄屏规则必须写在基础规则**之后**
2. `hidden` 只是 display:none：3000 行赛程表进入前先清空再分帧；分帧用 rAF+setTimeout 双保险
3. SDK 只有一个出口（platform.js）；握手超时不能取消订阅（晚到 ready 要恢复能力）
4. `renderAll` 只渲染可见视图；`applySnapshot` 后必须 `rebuildMatchIndex()`
5. `validateLoadedState` 不按「比赛是否在数据里」剔除预测（内置是窗口快照）
6. 榜单 only-if-better：分数未变优时 extra（昵称）也不更新——刷新昵称走 `submitBoardWithNick`（second+1 触发；0 胜 0 负同样适用）
7. `.env` 不进仓库；换票 secret 只进 FC 环境变量，不进任何客户端代码
8. 涉及页面呈现的修复，必须在调试台**看到真实渲染结果**才算验证——数据层单测/提交成功都不代表页面画得出来（renderBoard 崩溃曾被数据层验证掩盖 9 个版本）

## 8. 发版前检查清单

- [ ] 版本两处一致；构建带基址，产物 grep 到 OSS 域名、无凭据
- [ ] `remote versions` 无占位冲突；`remote info` network=enabled
- [ ] OSS `meta.json` 的 updatedAt 最新（采集管道健康，Actions 全绿不代表 OSS 没脱节）
- [ ] 真机过一遍：下注/结算/排行榜（**页面上能看到条目**）/昵称/分享/设置各子页返回层级；换票按钮（预览态跳过属预期，验正式版）
